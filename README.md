# Teamflow 團隊專案管理原型

繁體中文專案與任務看板，搭配 Excel 人員名冊及行動方案郵件草稿。

## 啟動與驗證

需要 Node.js 20 以上。

```sh
npm ci
npm run check
npm test
npm start
```

預設連接埠 3000，可設定 `PORT`。正式執行無需外部服務或 API 金鑰。`public` 可獨立靜態部署；ExcelJS 4.4.0 的瀏覽器套件與 MIT 授權已包含於 `public/vendor`，無須從 CDN 下載。更新該套件時須同步更新 vendored 檔案。

## 專案與任務

新增專案、建立／編輯／刪除任務，設定負責人、期限、狀態及優先順序；看板拖曳、清單、搜尋、篩選、統計及手機版介面。

- 人力分析：以目前或所有案件、負責人、搜尋文字與日期區間彙整任務狀態、待投入工時、最高同時未完成任務數及未估工時數。工時以日曆天平均分攤，已完成任務不計入待投入工時；未設定個人可用工時，並非超載或出勤判定。
- 案件甘特圖：以每日時間軸顯示起訖日與任務狀態，可水平捲動並點擊編輯。日期區間最多 366 天。
- 舊任務保留原資料，不推測起始日；缺少或無效排程列入待補排程，可點擊補齊。

任務亦支援起始日、預估工時、前置／接續任務、循環相依檢查、可接續任務與排程衝突提醒。

## Excel 人員名冊

進入「人員與通知」下載 .xlsx 範本，第一列為 `工號`、`姓名`、`Email`，後續列為資料。只讀取第一張工作表，檔案上限 2 MB、5,000 人。請將工號欄設定為文字以保留前置零。可接受替代欄名：員工編號 / Employee ID / EmployeeID、 人名 / Name、電子郵件 / E-mail。

選檔後先預覽新增、更新、不變數量與前 50 筆，確認後才套用。以工號為唯一識別：相同工號更新姓名與 Email，未列出的原有人員保留；同名不同工號可共存。重複工號、缺少必要欄位、空白姓名／工號或無效 Email 會阻擋整批更新。檔案損毀或加密也不會覆蓋原名冊。

任務可依姓名與工號選擇名冊人員，綁定的是工號，後續名冊更新會對應最新姓名及 Email。既有自由輸入的任務維持原狀，不依同名自動綁定，避免誤寄。

## 郵件與提醒

選擇名冊人員後，可從任務開啟 `mailto:` 預填郵件，內容取自目前表單；須由使用者的郵件程式確認寄出，不需 Outlook 整合。未儲存的表單內容只影響該次郵件草稿。

每個任務可分別為「待開始」「進行中」儲存不提醒、每天、每週（7 天）、自訂 1–365 天及提醒時間。時區記錄為 Asia/Taipei；已完成任務停止提醒，逾期任務仍依目前狀態的規則。這些是提醒設定草稿，尚無寄信服務、背景排程或自動提醒。

目前依使用者需求採手動上傳，後續再接排程 Excel 來源。真正的排程更新、自動寄信仍需共享後端資料庫、身份驗證、排程工作、寄信服務、重試與寄送紀錄；尚未選定寄信服務，不需提供金鑰。

## 資料與原型界線

所有專案、任務、人員、提醒設定與最後匯入紀錄只保存在目前網站來源、目前瀏覽器的 `teamflow.prototype.v1` localStorage。關閉頁面不會執行排程；不同使用者與瀏覽器不會同步，清除網站資料會遺失內容。網站尚無登入與存取控制，請使用測試名冊，不要把它當成正式工作紀錄或正式人事系統。Excel 在瀏覽器內解析，不傳送到伺服器。

## Netlify 部署

匯入 GitHub 儲存庫 `ayers1101-bot/license-search`，部署分支選 `main`。`netlify.toml` 已指定發布目錄 `public`，不需要 build command 或環境變數。推送至 main 後由 Netlify 自動部署。

## 多人協作測試版

入口為 `/team.html`，提供 Supabase Email 帳號、個人及共享專案、編輯／檢視角色、不可由一般帳號改寫的版本紀錄、擁有者審閱及時間點還原。啟用需要建立 Supabase 專案並執行資料庫初始化，完整步驟見 [SETUP-TEAM.md](SETUP-TEAM.md)。尚未設定服務時不開放登入。多人工作區與原有個人原型分開，不自動搬移資料。

## 三層子任務與拖曳排序

- 個人原型請切換「任務階層／排序」；多人版預設顯示任務階層，下方仍可展開狀態看板。
- 主任務可向下建立第一、第二、第三層子任務。每列按「＋ 子任務」，或在編輯視窗設定「上層任務」。改變上層會連同子任務一起移動，不允許循環、跨專案或移動後超過三層。
- 拖曳每列的 ⠿ 把手調整同一上層下的順序；主任務移動後其所有子任務會跟隨顯示。也支援上下按鈕及把手的鍵盤上下鍵。跨層拖曳會拒絕，不會暗中改變上層。
- 刪除任務會刪除整個子任務分支，先提示數量，並清除其他任務對已刪除任務的前置連結。個人版只有瀏覽器儲存；多人版會保存版本，擁有者可還原。
- 各層的負責人、期限、狀態與工時獨立，不自動彙總或連動。搜尋階層時會保留符合任務的上層脈絡。
- 層級使用 `parentId`，同層排序使用任務陣列順序；既有沒有 `parentId` 的任務視為主任務。資料沿用原本 JSON 文件，無需修改既有 Supabase 資料表或重跑初始化。
- 多人新增、編輯、刪除、排序仍透過既有權限及版本檢查 RPC；排序自動留下清楚的調整原因，歷史快照保留層級與順序。介面限制最多三層，既有資料庫不額外驗證任務層級。

## 管理者邀請制（取代自行註冊）

新增 Email 允許名單、首次設定顯示名稱及密碼、管理者核准／停用，以及 Netlify 伺服器邀請信端點。需要另套用增量 SQL 與後台設定；請依 [SETUP-INVITES.md](SETUP-INVITES.md) 執行，不要重跑原初始化。

## 多人與個人規劃功能一致

多人版已補齊人力分析、任務相依、甘特圖、看板／清單、搜尋篩選、工時優先、Excel 名冊與提醒設定，沿用原本權限與版本儲存，不需重跑 SQL。詳見 [FEATURE-PARITY.md](FEATURE-PARITY.md)。

## 甘特圖摘要顯示

主任務與三層子任務依階層成組，摘要條涵蓋下層有效時程。此彙總只影響畫面，不改寫原日期；搜尋保留上層且不縮短摘要，缺排程會明確提示。個人版與多人版同步適用，不需重跑 SQL。
