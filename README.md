# Teamflow 團隊專案管理原型

繁體中文的專案與任務看板，使用 Node.js 20+ 和原生瀏覽器技術，無正式執行所需的第三方套件。

## 啟動

```sh
cd /workspace/license-search
npm start
```

預設使用 3000 連接埠，可使用 `PORT=3001 npm start` 覆寫。服務不需要 npm install 或外部 API 金鑰。頁面與資源均由本機提供，不依賴外部字型服務。

## 可用功能

- 新增專案、切換專案，查看各專案任務統計與完成率。
- 新增、編輯、刪除任務；設定說明、負責人、截止日期、優先順序。
- 拖曳看板卡片切換狀態，或於清單模式使用狀態選單（支援手機操作）。
- 依標題、說明、負責人搜尋，以及依負責人篩選。
- localStorage 保存資料，重新整理後仍可使用；首次開啟有示範資料。
- Microsoft 365 / Outlook 整合規劃頁與未寄送的通知範例。

## 原型界線

資料僅存在目前瀏覽器的 `teamflow.prototype.v1` localStorage；不同瀏覽器、網域或使用者不會同步。清除網站資料會失去任務，請勿用於唯一的正式工作紀錄。負責人為自由輸入，尚無帳號、成員管理、權限、後端資料庫或附件。沒有實際寄信、讀取信箱或背景提醒。服務未提供正式部署所需的身份驗證。

## 後續 Microsoft 365 整合

正式版需先加入後端、資料庫與登入，再於公司 Microsoft Entra 租用戶註冊應用程式、設定回呼網址及授權。依功能需求採最小權限：登入可用 OpenID Connect；寄信評估 Microsoft Graph 委派 `Mail.Send`；郵件轉任務再評估 `Mail.Read`。公司政策可能需要管理員同意。背景寄信、排程、權杖安全儲存及重試需由後端處理。勿將應用程式密鑰或存取權杖存入前端程式或 localStorage。

## 開發檢查

```sh
node --check server.mjs
node --check public/app.js
```

瀏覽器驗收：新增專案與任務、編輯任務、切換清單狀態、拖曳看板、搜尋篩選、重新整理確認保存、刪除任務，以及手機版無水平溢出。Outlook 頁面只能預覽，不應觸發任何郵件請求。

## Netlify 測試網站部署

在 Netlify 選擇新增專案並匯入既有 GitHub 儲存庫 `ayers1101-bot/license-search`，授權 Netlify 讀取該儲存庫，部署分支選擇 `main`。根目錄的 `netlify.toml` 已指定靜態發布目錄 `public`，不需要 build command、環境變數或 API 金鑰。部署後以 Netlify 提供的 HTTPS 網址開啟；每次推送到部署分支會觸發更新。

驗收：確認頁面載入、新增任務、重新整理後保存，以及 Outlook 預覽。這是無登入的公開原型；任務資料僅存在各瀏覽器，不會跨使用者同步。正式上線前須加入身份驗證、後端資料庫與權限管理。
